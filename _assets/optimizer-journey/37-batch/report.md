# Layer37-B增长批量验证

2026-11-14，RTX4080 SUPER 32GiB，复用candidate39的5.28M参数Transformer、WikiText2数据及train-only BPE8192。序列128，微批量最大32。每运行32000条序列，共4096000 token。固定批量32；增长批量ceil(32*t^0.1)，末尾截断到相同token数。增长批量逐微批次累积，按样本加权平均后统一梯度限幅1。相同种子使用同一预生成样本位置序列。

Layer37使用Layer-no-budget实现，K8，尺度刷新保留原双向限幅。AdamW为PyTorch fused，beta1=.9，beta2=.999。共同20个基准批量的token warmup、按token cosine至0.1峰值；每步权重收缩为1e-4*(当前lr/峰值lr)。这不是理论文件的恒定步长、不裁剪、不衰减版本，不能据本实验验证理论收敛指数。

每组在种子11完整预算调参：Layer37学习率[.3,1,3]，AdamW[.0005,.001,.002]；全部选择中间值。确认种子22、33、44。共12调参运行及12确认运行。验证集选超参数，确认结束记录测试集，测试集不用于选择。

训练计时包含取批、前反向、梯度裁剪及优化器，排除验证和测试。没有GPU热身，单次运行很短，时间差仅作当前实现观察。增长批量最后一个不足32的微批次增加小kernel调用；因此耗时不代表理想动态批量实现的硬件上限。峰值是PyTorch allocated，不是进程保留显存或整卡占用。

结论：增长批量在同token预算使Layer37 NLL恶化.32162，AdamW恶化.22748。Layer37增长方案比固定方案训练慢约11.35%，虽然优化器时间减少约39.42%。没有支持其质量或整步效率优势。固定Layer37状态减少约50%，总峰值仅减少约3.13%；固定Layer37训练快约7.47%，NLL比固定AdamW高.18080，不能称相同质量提速。

更快的更新步数理论来自更多样本；本实验表明，当前任务和调参范围内它不能抵偿减少的参数更新次数。建议停止Layer37-B批量增长作为主候选，保留原Layer37作为低状态基线。
