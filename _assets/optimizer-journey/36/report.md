# 图片三行递推的复验

沿用原小型Transformer、数据划分、三种子22/33/44和每种子160步81920 token，不重新选学习率。原地核心m.lerp_(g,a)，p.add_(m,alpha=-eta*h)。额外实现foreach批量执行版本。完整Flash在线生成h,R，记录后由回放版本读取，同样的数据与初始化下核对递推。

|实现|更新核秒|控制器秒|训练总秒|验证CE|测试CE|
|---|---:|---:|---:|---:|---:|
|AdamW逐张量|2.42270|0|5.13612|2.46570|2.45768|
|AdamW foreach|.15049|0|2.85357|2.46570|2.45768|
|Flash三行逐张量回放|1.21888|0*|3.93675|2.54038|2.54169|
|Flash三行foreach回放|.06368|0*|2.85570|2.54038|2.54169|
|Flash完整在线参考实现|1.27669|3.66199|7.49793|2.54038|2.54169|

数字为三个种子的均值，时间单位秒。*回放控制信号来自完整运行，生成费用未计入回放时间，因此回放不是完整在线算法的端到端加速证据。记录读取开销计入训练时间。

Flash foreach纯更新比AdamW foreach少约57.7%时间（约2.36倍吞吐），支持图片三行更新核心更便宜。端到端训练却约2.856秒vs2.854秒，几乎一样：前反向传播、数据和其他开销占主导；这轮运行很短，不能解释千分之几秒差异为可靠排名。

Flash逐张量回放与完整实现的终点最大参数差为2.38e-7、2.38e-7、3.58e-7，损失基本相同。foreach回放测试CE也在浮点误差级一致。它们使用已有控制信号，统计上并非独立新种子。

上轮确实实现了图片的动量和参数递推，但使用了临时更新向量，并将噪声估计、范数归约和同步计入Flash总训练时间；不能以旧总时间否认三行核心的计算优势。本轮确认核心优势，同时完整在线版本的控制器仍占较多成本。尚未测量批量化/融合控制器的完整训练速度。

损失表现没有改善：当前完整门控仍未释放，图片简化没有改变已有h,R序列对应的优化行为。要把更新成本优势转为有效优化器优势，需要低成本地产生有用控制信号；本轮不证明已解决这点。

原始结果recheck_results目录，均值recheck_summary.json，等价性误差recheck_equivalence.json，代码simple_recheck.py。无重新调参，无额外测试集选择，无新增反向传播。计时排除评估，包含同步，未进行大规模预热与多轮随机顺序计时；AdamW逐张量首个种子有明显启动差异，应优先看foreach比较。
