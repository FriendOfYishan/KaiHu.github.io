# 51：消融 + 解耦权重衰减 + 40M token 长跑（2026-11-21）

**一句话结论：51 的数学结构是有效的（短预算上稳定赢 AdamW 0.060），但它赢的是"早期速度"而不是"终点质量"。
在 40M token、各方法都用自己的长预算最优学习率时，51 / 48 / AdamW 的最好验证 NLL 分别是 4.6874 / 4.6907 / 4.6842 ——
差距 ≤0.007，完全打平。所以要不要写融合核是"省显存/补速度"的问题，不是"再涨质量"的问题。**

## 0. 先回答你的问题：AdamW 是不是融合版？

**是。** 所有对比里的 AdamW 都是 `torch.optim.AdamW(..., fused=True)`（PyTorch 融合实现）。
51 现在是**未融合的纯 torch 循环**（逐参数、每步 5–8 个逐元素算子），所以墙钟差距全部来自实现：

|预算|AdamW(fused)|51(torch)|48(torch)|差距|
|---|---:|---:|---:|---|
|4.12M token（503 步）|24 s|36 s|—|+50%|
|40M token（4883 步）|226 s|345 s|281 s|+53%|

按你的要求我没有写融合核；等数学结论确定后再做。

## A. 短消融：收益来自哪两个部件（语言 4.12M token、lr=1e-3、种子 11/22/33）

|变体|做了什么|种子11|种子22|种子33|均值|相对 51|
|---|---|---:|---:|---:|---:|---:|
|**51**|完整候选|5.4518|5.4728|5.4907|**5.4718**|—|
|`51p48`|创新项增益 K 换成 48 的逐坐标 A₄₈|5.5593|5.5880|5.5539|5.5671|**+0.0953**|
|`51nc`|去掉 ±2 截断|5.5470|5.7358|5.5307|5.6045|**+0.1327**|
|`51nf`|去掉全张量份额（0.5/0.5 行列，无下限）|5.4776|5.4906|5.5020|5.4900|+0.0183|

读法：
1. **±2 截断是最重要的单件（0.133）**，去掉后还有一个种子跑到 5.736（不稳定）→ 它不只是"防爆"，是收益主力。
2. **50 的平方可加增益 K 值 0.095**：换成 48 的逐坐标 A₄₈ 就退回 5.567（比 48 的 5.607 好 0.04，说明"拆成历史+创新两项"本身也有一点用）。
3. **全局下限几乎没用（0.018，种子噪声内）**——它只保证"零动量坐标也有斜率"，在真实梯度里这种坐标很少。
4. 关于"只用 P 等于 48"：**不完全等**。51 的 P 用的是 `B⁻=M/(1−β^{t−1})`，48 用的是 `A₄₈·B_t`（`B_t=M/(1−β^t)`），
   两者还各自带自己的创新项；所以正确的对照就是上表的 `51p48`，不是"只用 P"。

## 结论（对数学公式的判定）

1. **代数结构是有效的**：把更新拆成"历史方向 + 本步新信息"，并把 50 的平方可加增益只用于新信息——这一改动在短预算上稳定赢 AdamW 0.060、
   在长预算上以一半的状态打平 AdamW。它不是伪收益（消融与 λ 对照都支持）。
2. **但它不提供终点质量优势**：40M token、各方法最优 lr 下 51 = AdamW（≤0.007）。收益的实质是"早期更快 ≈ 2% token"。
3. **收益来源已定位**：±2 截断（0.133）> 平方可加增益（0.095）>> 全局下限（0.018）。
4. **因此融合核的价值只在两个地方**：把优化器状态从 8 字节/参数降到 4 字节/参数（已实测 4.01 vs 8.00，峰值 −4%），
   以及把墙钟从 +53% 拉回到 ≤AdamW。**不要期待融合核带来质量提升。**
5. 若还想追"终点质量"：本 harness 里 40M token 已经进入过拟合区（16 epoch），要回答规模问题必须换到 45 轮那种 FineWeb-Edu 长跑格式
   （704M token 训练集），而不是继续在 WikiText-2 上堆 token。
